# Обновление до двух GPU-обработчиков

Это обновление заменяет только образы приложения и конфигурацию развёртывания.
PostgreSQL, Redis, их образы, именованные тома, каталог модели MonkeyOCR, файлы
заданий и существующий `.env.production` в пакет не входят и не удаляются.

В обновление входят:

- `specification-checker-api:0.1.2-stage6.20260806`;
- `specification-checker-worker:0.1.4-stage6.20260806`;
- production-файл Compose с сервисом `worker` (`WORKER_ID=worker-gpu-0`) на
  GPU 0 и сервисом `worker-gpu-1` на GPU 1;
- код очереди Redis с независимой регистрацией обработчиков и отдельными
  списками выполняемых заданий;
- единственный проверенный способ выполнения MonkeyOCR: SDPA, KV-кэш и
  проверенное ограничение числа пикселей. Отклонённый экспериментальный способ
  выполнения отсутствует.

Перед развёртыванием сохраните текущий `.env.production`. Удалите устаревшие
переменные профиля, механизма внимания и кэша MonkeyOCR, если они присутствуют,
и задайте:

```dotenv
MONKEYOCR_DTYPE=auto
MONKEYOCR_MAX_PIXELS=1003520
MONKEYOCR_MAX_NEW_TOKENS=
MONKEYOCR_PDF_RENDER_DPI=300
WORKER_LOCK_TTL_SECONDS=120
EXPECTED_WORKER_COUNT=2
```

Загрузка архива образов не останавливает работающую версию. Применение нового
файла Compose пересоздаёт API и первый обработчик, запускает второй обработчик
и сохраняет все именованные тома. Не используйте `docker compose down -v`.

После развёртывания ответ `/health` должен содержать `"worker_count":2` и
идентификаторы `worker-gpu-0` и `worker-gpu-1`.
